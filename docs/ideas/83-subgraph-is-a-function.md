# 子图即函数：签名、内联、没有调用栈

**状态**：在用（可改）

**一句话**：子图是图世界的函数——一次定义、命名、带类型化端口，多处实例化；默认在 validate 时内联，所以这门语言没有调用栈。

**动机**：没有子图的图只能表达一次性的流程，不能表达「这一类事情」。抽象是语言与流程图的最后一道分界：有它才有库、复用与带参数的模式。代价形状也合适——作者在声明时付一次，运行期每次兑现（[74](74-asymmetric-payoff.md)）。

**形态**：

签名四件：

- **方向与类型**：端口分输入输出，类型写在端口上。子图的签名就是图的函数类型；组合检查在 validate 时做，实参路径的产出形状与形参声明的形状一致才允许展开。
- **输出端口即返回值**：签名是输出端口的集合（名字 → 类型），调用点按名字绑定，多返回值不包成一条 record。一次调用只允许一个输出端口发火，否则调用者拿到的是歧义；顶层 plan 允许多个输出发火，run 的结果是实际发火的集合。
- **返回类型可以是和**：端口类型是带标签的和时，节点给每个变体一个端口、一次只发一个，签名就是这些变体类型的和；`option` / `result` 是它的特例（[90](90-types.md)、[89](89-edges.md)）。
- **默认值**：未接线的端口写字面量，声明期填入；运行期的「没有值」必须是一个值（Option），不是缺端口（[88](88-containers-and-joins.md)）。
- **只过端口绑定**：内部引用只能命名本图的步骤与本图的端口（[84](84-folding-fidelity.md)）。

实例化默认内联：步骤 id 加前缀，`$.步骤` 改写成新 id，子图入口接到调用点的入边，end 接到出边。展开只对源码里已有的实例化点做一次，深度与实例数各设上限，超限是编译错误——工作表，不是不动点（[57](57-linear-compile.md)）。内联只是一次性的模式；逐元素的模式（容器）见 [88](88-containers-and-joins.md)，它不复制图。

两条不平移的东西：

- **高阶**：把图当值传，只能让 call 的目标指向另一份 plan 的地址（独立 run），静态内联随之失去。
- **递归**：没有调用栈，递归只能被展开上限截断，或走独立 run。前者是静态展开，后者每次调用多一份 run 文档与一层归属。

**代价**：

- **内联是单态**：同一子图在两个调用点各展开一份，产物随实例数增长。这与单态化（[34](retired/34-monomorphization.md)）的代价形状相同，但实例集合由源码给定，不引入不动点。
- **独立 run 的调用要算层账**：取消、超时、配额按层算；父 run 在子 run 期间处于「等子 run」，这必须是模型里说得清的一种等待。
- **端口是硬边界**：想顺手读调用者的中间值就得加端口，小图会被迫变宽。这是刻意的，见 [84](84-folding-fidelity.md)。

**冲突**：[82](82-graph-is-the-semantics.md)（图是语义，子图是它的抽象层）、[84](84-folding-fidelity.md)、[85](85-graph-linearization.md)、[88](88-containers-and-joins.md)（另外两种实例化模式——逐元素与归约；「可选输入」未决项由它关闭——字面量与 Option 取代端口上的运行期状态）。
