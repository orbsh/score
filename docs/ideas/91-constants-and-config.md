# 常量与配置：常量节点，覆盖在 run 创建时

**状态**：在用（可改）

**一句话**：字面量是参数位上的立即数；要被命名、共享、覆盖的值做成常量节点（无输入、一个类型化输出），覆盖发生在 run 创建时并随启动参数记录。

**动机**：

- 正则、超时、阈值这类值是静态的，写在参数位上很自然；但部署时要改一个，不该去改图。
- 常量节点给出身份：可扫描、可渲染、可覆盖、可进日志。
- 与「数据不能定义或别名」不冲突：常量是程序的一部分（编译期已知），不是 run 里的值绑定。

**形态**：

- **立即数**：直接写在实参位，不进节点表；按参数位的类型解码。
- **常量节点**：无输入、一个类型化输出、一个值；下游接线引用它。多处引用就是扇出。
- **覆盖**：run 创建时按键覆盖；覆盖值记进 run 的启动参数，`plan_hash` 仍按定义算——程序身份不变，配置变。
- **分析**：扫描常量节点即得「有哪些可配置项」；立即数按参数位类型也可枚举，但没有名字、不可覆盖。
- **环境变量**：不走语言。配置注入走 run 创建时的覆盖；运行中要读就做成效果节点，读的时刻与值都进日志，重放是确定的。不设「环境变量常量」。
- **秘密**：secret 要么标记后不落日志（代价是重放不能重现），要么返回句柄、使用时才解析；默认落日志等于把密钥写进 run 文档。
- **与 seed 的区别**：seed 是反馈端口第 0 轮的值，用一次就退场（[88](88-containers-and-joins.md)）；常量节点是可以被任何下游随时读的值。别混成一个机制。

**代价**：

- **常量表要维护**：二进制里多一节，与类型表相邻（[87](87-binary-graph-is-the-artifact.md)）。
- **覆盖是 run 级的**：一次 run 内常量不变；中途要改只能新 run。
- **两种写法并存**：立即数与常量节点，规范要定——共享、要覆盖、要审计时才提升为节点，其余留在参数位。
- **secret 与重放二选一**：不能既要密钥不落盘、又要从文档完整重放。

**冲突**：[89](89-edges.md)（值的来源）、[87](87-binary-graph-is-the-artifact.md)（产物格式）、[90](90-types.md)（类型）、[88](88-containers-and-joins.md)（seed 不是常量）。

**若改掉会动到**：schematic 的 Plan（常量节点种类或常量表）、run 的启动参数、渲染（常量怎么显示）。
