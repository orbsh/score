# 容器与 join：实例化的两个参数

**状态**：在用（可改）

**一句话**：一个子图实例只定两件事——体内跑几次（一次性、map、flatmap、filter，即容器）与等到几个 token（zip、merge、collect，即 join）；两件都改就绪规则，所以都进内核，不做成库函数。

**动机**：

- 就绪规则不能被库函数改。普通节点是「输入齐了就跑」，zip 要两边都到，merge 任一边到就跑，collect 要够 n 个；调度器不认这些规则就不知道该等谁。
- 缺席要变成值。option 上下文让「上游没跑」也是一个 token（空值），消费者不必逐点判空；这比给端口加一个运行期的「可选」标志干净——那个第三状态一旦存在，readiness 就要分支。
- 不开放成通用 monad：bind 的顺序语义（State、IO）并行调度器兑现不了。上下文固定三种。
- 不叫 monad/functor：适用器是「怎么用」的属性，不是「是什么」的属性；同一张子图这里被 map、那里被 zip。子图只声明能力。

**形态**：

实例 = （子图，上下文，适用器，预算 max）。上下文固定三种：list / option / result。

适用器四种：

- **一次性**：内联（[83](83-subgraph-is-a-function.md)），整张图摊进调用点。
- **map**：逐元素跑体内子图，结果按元素序收集。
- **flatmap**：逐元素跑，拼接；顺序 = 元素序 × 内部序。
- **filter**：flatmap 的 0 或 1，不独立成一种语义。

上下文：

- **list**：元素独立，可并行。
- **option**：0 或 1 次，缺席自动穿过容器链——容器套容器时不必逐层判空。
- **result**：元素独立，失败作为值继续走。

join 是节点种类，不是库函数：

- **zip**：每个输入都有 token 才发一次，配成对。只到一边的 token 要排队，必须有上限或声明 last-wins。
- **merge**：任一到就发一次，不配对。schematic 今天「两条边进同一个点得到两趟」就是它。
- **collect(n)**：攒够 n 个发一次，输出一条 list；可能等很久，图上显示为 waiting 而不是 stuck。

seed：环的反馈端口在第 0 轮用一次声明的初值。它不是默认值（默认值分不清「还没到」和「这一轮没有」），也不是第二条边（一个输入端口只有一条边；再插一个合并就又要 join，而 join 自己也要 seed）。语义等价于 FRP 的 iPre。validate 查：每个环至少一个 seeded 端口，或一个只发一次的入口；环内至少一条边有 budget。

必需/可选删除：端口要么接线（引用），要么写字面量（默认）；运行期缺席必须是一个值。schematic 的「Optional inputs」因此关闭。

不拿 FRP 的：连续时间算子（integral、derivative、debounce）、switch（动态拓扑，静态审计与定价随之失效）、sample（读别人的最近值＝隐式依赖）。fold 不是容器：它跨元素携带状态，是环。

子图属性与状态（未定）：子图可以带属性；其中「状态」一项待单独裁决。支持的理由——一些场景里可变状态更直观、利于优化、数量可控、打包序列化可解；反对的理由——它把别名与写序带回模型，自动并行与确定性要靠约束守住。

**代价**：

- 运行文档变成矩阵：键要能表达（容器，元素，内层步骤，pass）；容器挂起时要保存哪些元素完成、哪些在等。
- 失败策略三选一（整体失败 / 元素 Result / 跳过），必须写进容器语义。
- 元素间默认串行还是并行要定：串行让 map 失去一半价值，并行要求体内无状态。
- 预算 max 是硬要求，否则宽度由数据决定，不可定价。
- 容器内挂起（内层 request 等人）会让一个实例同时有多种状态，渲染与调试都要按元素显示。
