# 折叠忠实：子图内部不得连到外部

**状态**：在用（可改）

**一句话**：子图与外界只通过端口相连，内部节点不得引用外部节点；这不是风格，是「图可以折叠成一个节点」的前提。

**动机**：折叠一个子图为一个节点，和提取一个函数是同一个动作。折叠只有在没有内部到外部的连接时才是忠实的；一旦允许穿透，折叠后的图会隐藏真实连接——图开始说谎。可渲染是这门语言的一等收益（[82](82-graph-is-the-semantics.md)），所以这条禁令是收益的前提，不是附加约束。

**形态**：

- **validate 规则**：子图内的引用只能命名本图的步骤或本图的端口；命名外部步骤是错误，报错要说出跨过了哪条边界（哪个子图、哪个调用者）。
- **两类穿透都要禁**：数据上的自由变量捕获（内部读外部步骤的输出）、控制上的非局部跳转（内部边连到外部）。前者更危险——它在图上不画出来；后者至少还有一条边可见。
- **外部依赖走声明式能力**：store、emit、resource、timer 这类是 ctx 服务，写进能力的声明里，不进图。这样「这个子图需要什么」在签名与能力表上看得见。
- **不给 unsafe 出口**：检查成本是一次前缀比较；它没有正当用途（端口已经覆盖）；unsafe 换的是检查成本，不是语义——这里丢掉的是组合性与折叠忠实，纪律恢复不了。

**代价**：不能就地复用调用者的中间值，必须显式传参；小图会被迫加端口。这是接线的成本，不是实现缺陷。

**冲突**：[83](83-subgraph-is-a-function.md)（签名是这条规则的出口）、[82](82-graph-is-the-semantics.md)。
