# 价值主张：AI 让写代码变便宜之后，编排层才是缺口

**状态**：在用（可改）

**一句话**：代码生成变便宜以后，瓶颈从「写」移到「发现错误的代价」；静态检查赢在有编译器当反馈环，score 因此站的位置是粗粒度编排——不替代 Rust，也不替代 Python，是接手那层最差的胶水。

**动机**：三条事实，按顺序。

- LLM 让写代码的边际成本大降，错误被发现的代价成为主导项。
- 静态语言把反馈环缩到编译一次：错误在编译期出现、措辞精确、能被 LLM 直接消费。对「规格已经清楚」的代码，LLM + Rust 的总成本低于 Python——这不是语言的胜利，是静态检查的胜利。
- Python 的优势退到两处：探索（规格还在形成时，宽松是资产）与库（只有 Python SDK 的工具）。两者都还在，但都不构成「编排层用 Python」的理由。

**形态**：

缺口在这里：跨工具、带等待、要恢复、要并行、要被人看懂的粗粒度流程。bash 没有类型、不能暂停、不能并行；Python 能，但检查点、并发、状态每一样都要自己写。重的那一头也不是它：Temporal 要服务与 SDK，activity 是代码；Argo 每步一个 pod，秒级；n8n 是低代码，规则写进 JSON 汤。

score 占的就是这一格：粗粒度、图即文档、可暂停、可审计、叶子语言任意。Python 退回节点——它的库优势一点不丢。

四条性质，各自对应一个缺口：

- **可视化**：图就是程序，渲染不是另画的图——看懂图就是看懂程序，调试也在图上。
- **结构化**：端口有类型、边有形状、validate 在跑之前拒绝；不是运行时才发现。
- **可并行**：值不可变、就绪即跑，分支不需要写并发代码。
- **可暂停**：run 文档就是续延，等人几天、换机器继续，都不占线程。

一条警告：不要把可视化读成低代码。用户是写 200 行 bash 的那个人；图是给他理解和调试用的，不是给不写代码的人搭积木。滑向低代码，语言那半就白设计了。

## 对 LLM 是否更友好

是，但有条件。

- **程序是数据**：图（JSON / KDL）不是长函数体。LLM 生成结构化数据的可靠性高于生成几百行过程代码；图还能增量生成——加一个节点、连一条边，每步都有可检查的中间态。
- **局部检查**：端口类型加 validate 给出编译器式的确定性错误，措辞稳定，反馈环短——与 Rust 编译器是同一种红利。
- **表面小**：没有循环、没有递归、没有可变状态；语义只有就绪、路由、等待。模型要记的规则少。
- **复用单位是定义**：子图定义一次、多处引用，省上下文也省 token；这是「存定义 + 实例」的直接收益（[87](87-binary-graph-is-the-artifact.md)）。
- **可回读**：渲染与文本都从同一份二进制导出，人读的和模型读的是同一个结构。
- **条件**：工具库要可枚举（[73](73-not-general-purpose.md)：工具库厚度是可用性下限），错误措辞要稳定——每次换一句话，反馈环就断了。叶子仍要人（或 LLM）写代码，Rust / Python 在节点里；那不是 score 的失败，是分工。

## 执行速度能到哪

四层，量级是估计，未实测：

| 层 | 成本 | 说明 |
| --- | --- | --- |
| 调度 | 每步亚微秒级 | 表驱动、一次分派、一次就绪检查；理论 10^6 步/秒以上 |
| 日志 | 50–500µs / 条（NVMe） | 真正的下限：2k–20k 步/秒；机械盘 ms 级降到 200–2k；按波次批量提交则 10k–100k+ |
| 节点内部 | 几十 ns 到 µs | 进程内 Rust；压实后的纯区同量级（[85](85-graph-linearization.md)） |
| 外部调用 | ms 到 s | 决定实际吞吐；等待时挂起，零成本——不占线程、不占内存 |

对比：Temporal 每个 activity 是一次服务往返加持久化（ms 级）；Argo 每步是一个 pod（秒级）；bash 每步一次进程启动（ms 级）。

结论：score 的卖点不是「比 Rust 快」，是「每步便宜、等待免费、日志是唯一地板」；批提交把地板压低，而且和 okm 的 batch 提交是同一条路（[93](93-score-and-okm.md)：效果与日志同批）。

**代价**：

- **通用词做名字**：搜索与商标难独占，必须先有域名与组织（[86](86-name-score.md)）。
- **容易被读成低代码**：销售与文档都要反复划界，一次说漏就归错类。
- **速度那张表是估计**：不实测不能对外报数。
