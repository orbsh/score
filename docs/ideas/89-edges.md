# 边：端口到端口，一条入边

**状态**：在用（可改）

**一句话**：一条边是（源节点，源输出端口）→（目标节点，目标输入端口），携带一个值；一个输入端口只有一条入边，扇出随便，合并必须显式。

**动机**：

- 节点到节点表达不了「多输出里的哪一个」和「多参数里的哪一个」；端口到端口把这件事变成结构，而不是约定。
- 一个端口多条入边会说谎：谁来、先来后到、是否配对，全是隐式规则。合并是语义选择（zip / merge / collect），必须画成一个节点。
- 数据边是唯一的边：纯依赖就是携带单位值的数据边，没有第二套「控制边」。

**形态**：

- **普通**：A.out → B.x，值随 token 走。
- **扇出**：一个输出端口多条出边；值不可变，读不复制。
- **合并**：显式 combine 节点（[88](88-containers-and-joins.md)）；zip 配对、merge 每 token 一次、collect 够 n 个。
- **分支**：互斥由源决定（一次发一个标签），`*` 兜底必须存在；谓词是表面糖，在声明门降级成 selector 节点。
- **变体分支**：输出类型是带标签的和时，节点可以给每个变体一个端口，一次只有一个发火——与 selector 同为源侧互斥，标签从运行期字符串换成编译期变体名。边仍然只接端口，不给边加第二种派发语义。
- **环**：回边不声明，由 SCC 找出；反馈端口带 seed；环要有 budget——`u64`（pass 上限）或显式 `unbounded`；终止走 selector 的出口，不回边。无界环让整个计划被 validate 标为非终止：定价失效，运行时要求取消信号——它属于 service run 那一类（[92](92-streams-and-batches.md)），不是「把上限调大」。墙钟预算（`30s`）是另一个轴，管 SLA，不替步数管成本。
- **失败**：节点有 `failed` 输出端口，失败路径就是普通边——不引入「状态条件」这种第二套谓词。
- **多输出**：输出节点是汇；每个输出节点一个输入端口，图的返回是它们实际发火的集合（[83](83-subgraph-is-a-function.md)）。
- **子图**：边不跨边界，只接端口；内联时重写，容器不复制图（[88](88-containers-and-joins.md)）。
- **挂起与分布**：token 随 run 文档持久化；跨挂起或跨机器的值已经是字节（[87](87-binary-graph-is-the-artifact.md)）。

**代价**：

- **端口必须命名**：位置实参在渲染、子图重构、多输出面前都会错位。
- **一条入边会多出节点**：「两个上游都可能供值」必须画一个 combine；小图因此变宽。
- **条件需要一个求值器**：谓词落在 selector 上，叶子因此存在（[82](82-graph-is-the-semantics.md)）。
- **穷尽性要查**：变体端口要么被接、要么显式忽略，否则 validate 拒绝——漏一个变体是编译期错误，不是运行时空转。
- **环的判定是编译期的**：SCC、seed、budget 都是 validate 的活，配错是拒绝而不是运行期挂死。
- **无界是一类不同的运行对象**：它让「run 会结束」这条不再成立；定价、配额、告警、托管计费都要跟着换口径。
- **预算是两个轴**：步数管成本，墙钟管 SLA；只给一种，另一种就会被人用错（拿步数当超时，或拿超时当预算）。
