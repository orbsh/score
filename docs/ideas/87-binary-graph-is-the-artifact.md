# 二进制图是本体

**状态**：在用（可改）

**一句话**：语言的权威形式是一份二进制图——程序就是它；文本只是把某种写法生成为这份二进制的一个来源（可以有多套），渲染是同一份二进制的投影。

**动机**：

- 与 Lisp 的差别要补上这一点：Lisp 的 AST 活在内存里，列表是文本，没有一份规范的二进制程序。这里二进制图同时是语义、交换格式与存储格式。「从图数据库导出即能用」就建立在这条上。
- 文本不是权威，解决两个问题：多种写法（KDL、JSON、图形编辑器）都能生成同一个程序，不必回答「哪份文本是真的」；文本的丢失（注释、空白、书写顺序）不影响程序的身份。
- 程序的身份是内容哈希（schematic 的 `plan_hash` 由宿主算），不是文件路径，也不是某份文本。

**形态**：

- **本体**：二进制图。第一个版本就是 schematic 的 plan 编码，格式版本随它走。模型不另起一套：引擎现在是 schematic（独立的一套库，声明解析与 validate 都在里面），语言要加的东西（子图、端口、结果类型）先进 schematic 的模型，再由语言使用。将来语言成熟、用自己的引擎替换 schematic 时，换的是 validate / ready / advance 的实现，不是格式——这是「兼容 schematic 的模式」的具体含义。
- **来源**：文本是前端之一，可以有多套。[71](71-kdl-surface-syntax.md) 的折中（KDL 只覆盖图这一层）是候选。每个前端只做一件事：把文本生成为同一份二进制。不要求反向唯一——从二进制导出的文本可以丢掉原文的写法，程序没有丢。
- **渲染**：从二进制图直接投影（分层、折叠、按尺寸 LOD），不从文本重画。折叠的忠实性（[84](84-folding-fidelity.md)）因此是格式层的性质，不是编辑器的性质。
- **图库导出**：从图数据库导出一个子图，就是一份 plan。但导出必须满足 plan 的形状（有 end、环有 budget、引用指向有保证的生产者），否则 validate 拒绝。导出即用，不等于导出即合法。
- **执行**：二进制图编译成字节码或其它目标（[85](85-graph-linearization.md)）；图本身不被改写。

**代价**：

- **二进制成为存储格式，就要背版本兼容**：`schema_version` 与格式版本的每次跳动都要有迁移或拒绝策略。文本格式可以随手改，二进制不行。
- **多前端会不同步**：同一程序有两种写法，就有「哪种能表达全部」的问题。规则要写死：前端只能是二进制的子集或等价生成器，不允许扩展语义。
- **图库里的子图带存储属性**（id、时间戳、标签），导出时要丢弃或归一化，否则「导出即用」会带进一批冗余字段，而 validate 不知道该怎么看它们。
