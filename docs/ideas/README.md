# 想法目录：一份文档一个想法

这里没有「方案」，只有想法。每条想法一份文档，可以互相矛盾，也可以和已实现的东西矛盾。不采用的想法移到 [retired/](retired/README.md)，不留在主目录里。

## 规则

- **一条想法一份文档**。不合并、不归并成「结论」。文档之间冲突是常态，冲突在双方文档里各自登记，不设裁判。
- **状态四档**：`在用`（当前草案里这么写，随时能改）、`候选`（还没定的另一个做法）、`未定`（要什么还没想清）、`不采用`（已归档，头部「结局」行写为什么）。
- **不采用的方案归档，不删除**。文件移到 `retired/`，头部加一行「结局」说明为什么不用；在主目录里它就等于不存在。保留作参考但已不描述当前语义的文档，也写「结局」，标明还剩哪一部分适用。
- **没有终态**。写进 `在用` 的意思只是「现在这么写」，不是「已经定了」。改一条想法只需要改那一条文档，不需要全局保持一致。
- **不写否决理由，只写代价**。代价是「这么做的开销在哪」，不是「所以不该这么做」；同一条代价在另一份文档里可以是优点。
- **示例按写作时的表面书写**。当前表面只在 [语法总表](../reference/syntax.md) 里冻结；想法文档里的片段只说明那一条想法，不与总表同步更新。
- **允许空**。想法可以先只有一句话和一句动机，形态以后再补；空着比填一个假的定论好。

## 模板

```
# 一句话标题（想法本身，不是话题）

**状态**：在用 / 候选 / 未定 / 不采用
**结局**：不采用 / 参考——为什么（只有归档与保留文档写这一行）
**一句话**：
**动机**：
**形态**：
**代价**：
**冲突**：指向冲突的那份文档，说明冲突在哪
**若改掉会动到**：哪些文档、哪些语法/机制跟着变
```
